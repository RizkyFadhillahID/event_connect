1️⃣ Autentikasi (Authentication)

Login & Logout

Sistem autentikasi menggunakan Laravel Sanctum dengan Bearer Token.

POST /api/login
POST /api/logout
GET /api/me

Fitur: Email + Password, Sanctum token di localStorage, auto-logout on token invalid

2️⃣ Manajemen User (Role-based)

CRUD User & Role Assignment

Superadmin Only

GET /api/users
POST /api/users
GET|PUT|DELETE /api/users/{id}

14 Role Tersedia:

  • superadmin, project_manager (Full access)
  • event_planner, promotion_team, partnership_manager
  • budgeting, operations_team, creative_team
  • rundown_coordinator, talent_coordinator
  • registration_guest_management, technical_team
  • documentation_team, liaison_officer

View: Tabel user + Modal create/edit, search filter, pagination

3️⃣ Manajemen Event

Full Event Lifecycle Management

PM + Superadmin (CRUD), All Users (View)

GET /api/events
POST|PUT|DELETE /api/events/{id}
GET /api/events/{id}/personnel
GET /api/events/{id}/tasks

Fitur:

  • 5 Status: Draft → Active → Ongoing → Completed → Cancelled
  • Track: Lokasi, Budget, Kategori, Target Peserta
  • Team Management: Tambah/hapus personel dengan role jabatan
  • Task Integration: Lihat task stats dan daftar task per event

View: Tabel events + Modal detail (info + personnel + task stats)

4️⃣ Task & Workflow Management

Kompleks Task Coordination dengan Hierarki + Event-Mandatory UX

All Authenticated Users

API Endpoints:

  • GET /api/tasks — List dengan filter (event, assignee, status, prioritas, overdue, my_tasks)
  • POST /api/tasks — Buat task baru
  • GET|PUT|DELETE /api/tasks/{id} — Detail, update, hapus
  • PATCH /api/tasks/{id}/status — Update status cepat
  • GET|POST /api/tasks/{id}/comments — Thread komentar
  • GET /api/my-tasks — Task milik user login (limit 20)
  • GET /api/events/{id}/tasks — Semua task + statistik per event

Frontend menggunakan Event-Mandatory Pattern: user wajib pilih event sebelum melihat/mengelola task.

5️⃣ Timeline & Rundown Management ⭐ Baru

Execution Layer untuk Agenda Hari-H Event

Role-scoped (lihat tabel akses)

11 API Endpoints baru:

  • GET|POST /api/events/{event}/rundowns — List + buat item
  • GET /api/events/{event}/rundown-dates — Tanggal unik
  • GET /api/events/{event}/rundown-stats — Statistik completion & delay
  • GET|PUT|DELETE /api/rundowns/{rundown} — Detail, update, hapus

Execution Layer di atas Task Planning Layer

Update: TasksView — Event-Mandatory Pattern

UX Redesign: Pilih Event Dulu, Baru Kelola Task

TasksView kini mengikuti pola yang sama dengan RundownView: user wajib memilih event terlebih dahulu sebelum melihat atau mengelola task.

Phase 1 — Event Selection Screen

  • Search bar untuk filter event by nama / lokasi
  • Grid kartu event: nama, lokasi, tanggal, status badge
  • Setiap kartu menampilkan task stats: Total, Aktif, Selesai, Overdue + progress bar %
  • Klik kartu → masuk ke Phase 2 (task management untuk event tersebut)
  • Event selection tersimpan di localStorage dan dibaca kembali saat halaman dibuka ulang
  • Deep-link support via URL param ?event_id=X (dari EventsView)

Phase 2 — Task Management Screen

  • Context Bar di atas: tombol "Kembali", nama event aktif, chip lokasi/tanggal/status, stats bar real-time (Total / Aktif / Selesai / Overdue + progress)
  • Filter bar tanpa event dropdown (sudah terkunci ke event terpilih)
  • Kanban Board & List View seperti sebelumnya, hanya task event terpilih yang ditampilkan
  • Modal Create/Edit: field Event read-only (pre-filled dari event terpilih)
  • Stats bar otomatis refresh setelah create, update status, atau delete task
